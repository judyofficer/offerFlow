# 《offerFlow 大学生求职工作台》产品需求文档 (PRD)

## 一、项目核心定位
摒弃**“简历编辑器”**这种狭窄定位，产品定义为**求职全生命周期管理系统（Career OS / JobFlow）**。
区别于市面上单一简历工具：它不只是简历编辑工具，而是一套完整求职工作台，覆盖从求职准备、岗位投递、面试跟进、Offer对比到求职数据复盘的完整链路。

### 项目优势（适合作为个人项目的核心理由）
1. **需求真实可持续**：目标用户为应届生，本人即是长期使用者；秋招结束可延伸至春招、实习、社招持续迭代；
2. **赛道差异化**：避开商城、博客等烂大街模板项目；市面上工具大多只做简历，缺少求职全流程一体化管理；
3. **技术落地自然**：各类工程能力依托真实业务场景实现，不需要强行堆砌技术炫技；
4. **面试友好**：业务场景贴近校招求职，面试官容易产生共鸣，具备充足的拓展讨论空间。

## 二、完整业务模块（求职生命周期分层）
```text
准备阶段
├── 技能学习档案
├── 项目经历管理
├── 简历编辑器 + 多版本简历管理

投递阶段
├── JD收藏与技能解析
├── 岗位投递记录
├── 内推信息管理

面试阶段
├── 面试日程、时间提醒
├── 面经题库管理、面试录音整理
├── 面试复盘记录

Offer阶段
├── 多份Offer横向对比
├── 薪资、城市、截止日期管理

总结阶段
├── 求职数据漏斗统计、可视化分析
```

### 六大核心差异化功能亮点
1. **简历版本控制系统（最高优先级亮点）**
对标 Git 设计：针对不同岗位维护独立简历版本，支持版本 Diff 对比、历史回滚、标签管理，解决学生多份简历混乱命名痛点。
2. **JD结构化解析**
粘贴 JD 自动提取岗位技能关键词，统计投递岗位技能需求分布，生成个人技能画像，直观看到市场技能要求趋势。
3. **投递状态流水线**
标准化求职状态机：未投递→已投递→笔试→一面→二面→HR面→Offer→结束，可视化求职 Timeline。
4. **结构化面经管理**
按公司、岗位、题目、回答、复盘、标签组织面试题，支持全局全文检索，沉淀个人面试知识库。
5. **求职数据看板**
投递总量、回复率、面试转化率、Offer转化率等指标，生成漏斗图、时间趋势图表。
6. **日程日历提醒**
统一管理面试时间、Offer截止日期，主动推送提醒。

### 模块D：面试与面经复盘 [已砍掉 (Out of Scope)]
> **架构决策 (ADR-005)**：为聚焦核心的数据追踪闭环，避免与专业笔记软件（如 Notion, Obsidian）形成冗余竞争，MVP 阶段彻底砍掉富文本面经模块。用户可通过在投递详情里附带外链的方式进行记录。

## 三、可落地的技术亮点（由浅入深，贴合业务）
优先围绕用户体验实现，复杂中间件后期迭代增加：
1. **编辑器防抖自动保存**：无需手动点击保存，实时持久化、意外断电恢复；
2. **简历版本Diff算法**：对比不同简历版本内容差异，实现变更预览与版本回滚；
3. **数据与视图分离**：同一份简历数据源，切换多套简历模板，统一导出PDF；
4. **PDF定制导出**：解决分页、字体、打印适配等工程常见问题；
5. **全文检索引擎**：简历、面经、JD统一索引，关键词检索+内容高亮；
6. **离线编辑能力**：基于IndexedDB实现无网编辑，在线后双向同步，处理数据冲突；
7. **进阶拓展**：多端同步、实时协作改简历、插件化模板系统、操作审计日志、大数据量渲染性能优化。
